# 官方审核数据与前台替换设计

## 目标

将已采集的八路军西安办事处纪念馆官网资料整理为审核数据集，并替换前端的馆情、文物、展览和参观服务演示数据。前端使用静态数据模块，不在运行时读取 crawler；不继续采集、不创建后端、不连接数据库。

## 审核数据

从 Node 采集器的 raw JSON 生成 `crawler/node/output/reviewed/museum.json`、`relics.json`、`exhibitions.json`、`visit.json`。每条数据保留官网来源、采集时间、`verified: false` 与 `reviewStatus: "pending"`，并增加 `frontendReady: true`。这表示展示结构已整理，不表示史料真实性已最终确认。

馆情使用官网正文和基于正文的短摘要，标记 `summaryGenerated: true`。9 件文物和 3 个展览保留全部官网字段；类别、年代、日期缺失则保留空字符串。封面优先使用官网正文内的第一张图片，只有完全没有图片才使用统一前端占位图。参观服务只映射官网返回的开放时间、闭馆规则、交通、讲解、服务须知与预约说明；地址始终保持空字符串。

## 前端数据与页面

审核 JSON 转换为 `frontend/src/data/museum.js`、`relics.js`、`exhibitions.js`、`visit.js` 的静态模块。模块中统一定义来源、采集时间和图片 URL；Vue 页面不写入大段内容，也不访问 crawler。

首页仅显示馆情短摘要和官方文物精选；走进纪念馆显示完整馆情；文物和展览页面展示官方条目；文物详情以安全清理后的 HTML 正文渲染，并在图片加载失败时退回统一占位图。参观服务显示官方字段，地址位置使用“地址信息待补充核实”，页底提示信息可能调整。

官方数据的详情页底部统一显示官网来源与采集日期，不显示内部 API 地址。

## 空资料和安全渲染

`courtyards`、`news`、`history`、`people` 没有可靠官网数据，保留已有演示数据，但添加 `isPlaceholder: true` 与“资料整理中 / 待史料核实”标识。人物使用统一剪影/资料整理中占位图，不保留 AI 风格人物头像。

正文只使用已在采集阶段清理过的 HTML，并在渲染前做最小白名单净化，移除 script、style、iframe 和事件属性。官网图片仅作开发预览外链，不批量下载。

## 验收

运行前端测试和 Vite 构建；核查首页馆情、文物列表/详情、展览、参观服务、图片 fallback 和移动端。所有审核 JSON 与前端数据保持 UTF-8，未改动后端或数据库，且没有任何未获官网数据支持的自动补充。
